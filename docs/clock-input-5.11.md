# 开发版 5.11 · 窗口入口与时钟音量

## 窗口第一次打开

此前只把设置按钮接入 `settings_open`，完整日程管理、事项、闹钟与通知仍直接在 App 借用内处理：隐藏进程的第一次 ShowWindow 可能受 STARTUPINFO 覆盖；模态或重入借用会直接丢弃请求。闹钟入口甚至没有显示主窗口。

现在所有主窗口入口携带目标页／日期／事项进入同一条激活路径。借用忙或 owner 被模态禁用时保留请求，窗口内容准备结束后释放 App 借用，再显示、恢复最小化、激活。成功显示后才隐藏普通来源日历；分离日历保留。专注快捷入口用单一请求携带目的页，不再分开发送“切页”和“显示”。日历更新时点击完整管理也保留到下一次定时处理。跳转前收集设置草稿，错误输入不被强行覆盖。

回归从真实隐藏启动子进程和非输入桌面运行，复现时五项全部失败；修改后通过。测试覆盖日历设置图标、完整管理、事项、闹钟、专注、通知、托盘设置、单实例请求、最小化启动、主 App 和日历分别重入、模态 owner、来源交接、135 次混合入口及设置草稿保留。

## 音量操作

“时钟显示”提供两个独立开关，默认开启：

- 时钟滚轮调音量：每个标准滚轮刻度 2%，高精度滚轮累计不足一格的增量；音量限制 0–100%。滚轮不改变静音状态。
- 时钟中键静音／恢复：切换当前默认输出设备的静音状态，保留音量值。

仅在接管的时钟 XAML 元素内订阅 PointerWheelChanged / PointerPressed。核对当前相对坐标，忽略横向滚轮及非中键按下；不在 QQ 内处理音量。选择系统日历不影响这两项开关。停用或失联时，和时钟其他订阅一起撤销。

原生事件沿既有窗口、进程、会话、时钟目标及序号校验发送到宿主。音量动作不进入日历打开队列，在独立 MTA 线程用 Core Audio 操作当前默认播放设备；每次重新解析设备以支持切换耳机／扬声器。队列有界，Explorer 不执行音频 API。

验证包括协议选项独立性、重放／非法增量拒绝、实际 XAML 委托接口与订阅释放、系统日历保留、开关保存和页面缓存，以及真实 Core Audio 工作线程降低音量、静音两次、恢复原状态。对任务栏后台投递 WM_MOUSEWHEEL 的尝试未产生真实 XAML 指针事件，不能算手势通过。当前电脑自动化接口未暴露任务栏窗口；真实鼠标从时钟事件到系统音量的完整交互仍需人工验收。主副屏接管的只读检查与音频后台测试分别记录，不互相替代。

## QQ 弹窗兼容

QQ 副屏悬停卡片定位是独立的实验性兼容项，默认关闭，旧配置缺少该字段也按关闭处理。停用时撤销线程钩子及定位租约，默认模式不启动接入线程、不查找 QQ、不加载定位 DLL。常规托盘复制、时钟、日历、音量继续工作。

此兼容项通过 Windows 线程消息钩子将 DLL 加载进 QQ 进程，确实属于进程内接入。处理范围是卡片位置，不读取聊天内容；但这不能证明 QQ 安全检测一定接受，无法保证没有账号风险。开启前界面直接说明这一点。曾加载的模块因已有窗口回调而保留，需等 QQ 自然退出释放，不能强行卸载。

关闭后的代价：QQ 卡片可能再次出现在主屏。无需因此关闭其他托盘功能。
