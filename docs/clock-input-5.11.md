# 开发版 5.11 · 窗口入口与时钟音量

## 窗口第一次打开

此前只把设置按钮接入 `settings_open`，完整日程管理、事项、闹钟与通知仍直接在 App 借用内处理：隐藏进程的第一次 ShowWindow 可能受 STARTUPINFO 覆盖；模态或重入借用会直接丢弃请求。闹钟入口甚至没有显示主窗口。

现在所有主窗口入口携带目标页／日期／事项进入同一条激活路径。借用忙或 owner 被模态禁用时保留请求，窗口内容准备结束后释放 App 借用，再显示、恢复最小化、激活。成功显示后才隐藏普通来源日历；分离日历保留。专注快捷入口用单一请求携带目的页，不再分开发送“切页”和“显示”。日历更新时点击完整管理也保留到下一次定时处理。跳转前收集设置草稿，错误输入不被强行覆盖。

回归从真实隐藏启动子进程和非输入桌面运行，复现时五项全部失败；修改后通过。测试覆盖日历设置图标、完整管理、事项、闹钟、专注、通知、托盘设置、单实例请求、最小化启动、主 App 和日历分别重入、模态 owner、来源交接、135 次混合入口及设置草稿保留。

发布包检查命令：

```powershell
.\tools\Test-MainWindowOpen.ps1 -Executable 'dist\LiteTray-5.11.0\LiteTray.exe' -Label '5.11-hidden' -AuditPages
```

## 音量操作

“时钟显示”提供两个独立开关，默认开启：

- 时钟滚轮调音量：每个标准滚轮刻度 2%，高精度滚轮累计不足一格的增量；音量限制 0–100%。滚轮不改变静音状态。
- 时钟中键静音／恢复：切换当前默认输出设备的静音状态，保留音量值。

仅在接管的时钟 XAML 元素内订阅 PointerWheelChanged / PointerPressed。核对当前相对坐标，忽略横向滚轮及非中键按下；不在 QQ 内处理音量。选择系统日历不影响这两项开关。停用或失联时，和时钟其他订阅一起撤销。

原生事件沿既有窗口、进程、会话、时钟目标及序号校验发送到宿主。音量动作不进入日历打开队列，在独立 MTA 线程用 Core Audio 操作当前默认播放设备；每次重新解析设备以支持切换耳机／扬声器。队列有界，Explorer 不执行音频 API。

验证包括协议选项独立性、重放／非法增量拒绝、实际 XAML 委托接口与订阅释放、系统日历保留、开关保存和页面缓存，以及真实 Core Audio 工作线程降低音量、静音两次、恢复原状态。对任务栏后台投递 WM_MOUSEWHEEL 的尝试未产生真实 XAML 指针事件，不能算手势通过。当前电脑自动化接口未暴露任务栏窗口；真实鼠标从时钟事件到系统音量的完整交互仍需人工验收。主副屏接管的只读检查与音频后台测试分别记录，不互相替代。

## 5.11.1 音量百分比

滚轮或中键操作完成后，音频线程从实际设备读回百分比和静音状态，显示在发起操作的时钟旁。静音时保留百分比并标明“已静音”；设备不可用时显示错误提示，不编造音量值。沿用已有两项音量开关，无需新增配置。

浮层为 208×72 逻辑像素，使用 SVG 喇叭图标、DirectWrite 百分比和音量进度条，跟随系统／应用明暗主题。按时钟所在显示器的工作区及 DPI 定位，保持置顶且不激活窗口、不截获鼠标；最后一次操作约 1.4 秒后收起。快速滚动合并为最新读回值并复用同一窗口，过期结果不会重新弹出。显示器变化或宿主退出时清理窗口。

真实 Core Audio 工作线程检查了音量降低、两次静音以及反馈百分比／锚点，结束后恢复原音量和静音状态。非输入桌面检查两屏浮层、明暗主题、0%／24%／100%及不可用设备、窗口复用、焦点保持、鼠标穿透和自动收起；布局测试覆盖四边任务栏、负坐标及 100%–200% 缩放。离屏绘制证据在 `local/ui5111-volume/`。本次只改宿主，任务栏适配 DLL、QQ 兼容项及用户配置保持原样。

## 5.11.2 中键与展开日历冲突

中键静音在 PointerPressed 发布成功后设置 Handled，但 XAML 随后仍可能独立产生 Tapped。旧 Tapped 处理不保留按键手势信息，因此同一次中键操作又发布了打开日历的 Pointer。隔离回归通过真实 XAML 元素和生产委托重放事件，修复前得到 `[VolumeMute, Pointer]`，能直接检测这次冲突。

现在每个时钟订阅保留已接收的静音手势状态，在下一次指针按下或完整解除订阅前消费其后续 Tapped，不再打开 LiteTray 面板，也不把该点击交给系统日历。新的左键／触摸／笔按下重置状态，因此中键取消或未产生 Tapped 也不会吞掉下一次正常操作；发布失败不标记静音手势。托盘定时刷新会临时暂停、恢复订阅，必须保留该状态，否则长按中键跨过刷新仍会误开日历；回归也复现并覆盖此边界。没有增加全局鼠标钩子或按时间猜测点击的延迟。

回归覆盖两种日历选择、反复中键及重复 Tapped、未产生 Tapped 后接左键／触摸、发送失败、停用与重新激活。命令为 `tools/Test-XamlClock.ps1 -BinaryPath <exe>`；事件参数夹具提供按键属性，命中测试、生产委托、发布和真实 WinRT Tapped 参数按原路径执行。它是可重复的事件链回归，不等同于操作真实鼠标。此次修改任务栏适配 DLL，更新运行实例需要重载 Explorer。

## 5.11.3 普通面板点击外部收起

未分离的日历面板在鼠标按下面板外区域时收起，包含桌面空白、已在前台的程序、其他窗口和任务栏；面板内控件及其拥有的下拉／弹出窗口保留。点击时钟左键仍由点击释放时的原有开关处理，避免按下收起、释放又展开；中键在外部执行静音时也收起普通面板。分离后不因外部点击或失焦收起。

原实现每 50ms 采样一次按键状态，完整落在两次采样之间的快速点击会丢失；打开后的 250ms 保护期及前台窗口首次采样也可能把外部点击忽略。现在只有普通面板可见时注册本进程的鼠标 Raw Input，按消息产生时的位置和时间处理按下事件；不会抑制原始点击或阻止其到达其他程序，也不往第三方进程加载 DLL。隐藏、分离和销毁时注销。如果本进程其他组件已经占用该注册，不替换它，退回焦点处理和原有采样。

Raw Input 的真实按下事件不受打开保护期限制；过期开启前的排队事件不收起新面板。失焦到其他窗口也会收起普通面板，但保留打开瞬间 Explorer 焦点回跳的保护。回归包含快点击、同一前台程序、五种鼠标按键、面板内部、关联弹窗、时钟开关、中键、过期事件、分离模式，以及原生输入注册、接收目标切换和注销。行为回归使用非输入桌面和按键事件参数，不操作用户桌面的物理鼠标。

## 5.11.4 设置关闭与未保存提示

旧版 `WM_CLOSE` 只隐藏设置窗口，草稿一直留到退出进程时才确认。另有一个可独立复现的误报：“复制主屏托盘图标”复选框展示 `enabled && show_icons`，收集页面时却把两个字段都赋为复选框值，因此默认配置只浏览该页也会被判定为修改。现在仅在复选框的实际状态改变时更新这两个兼容字段。

关闭设置窗口与退出程序共用保存决策：无修改立即继续；有修改在当下选择保存、放弃或取消。放弃会恢复已保存配置并销毁缓存页中的输入；取消保留窗口，格式错误或写入失败也保留窗口和输入。设置页面仍通过“保存设置”显式应用，不因关闭而静默保存。

非输入桌面回归驱动真实控件和 `WM_CLOSE`，覆盖所有页面双向浏览、两项托盘字段的四种组合、取消、跨页草稿放弃、缓存清理、成功保存、格式错误和实际文件写入失败，最后执行生产退出路径检查无重复提示。`LITETRAY_SETTINGS_PROFILE_CHECK` 可指定只读配置副本，额外验证既有设置的往返读取；本次也检查了当前用户配置。所有保存测试使用独立临时目录。

## QQ 弹窗兼容

QQ 副屏悬停卡片定位是独立的实验性兼容项，默认关闭，旧配置缺少该字段也按关闭处理。停用时撤销线程钩子及定位租约，默认模式不启动接入线程、不查找 QQ、不加载定位 DLL。常规托盘复制、时钟、日历、音量继续工作。

此兼容项通过 Windows 线程消息钩子将 DLL 加载进 QQ 进程，确实属于进程内接入。处理范围是卡片位置，不读取聊天内容；但这不能证明 QQ 安全检测一定接受，无法保证没有账号风险。开启前界面直接说明这一点。曾加载的模块因已有窗口回调而保留，需等 QQ 自然退出释放，不能强行卸载。

关闭后的代价：QQ 卡片可能再次出现在主屏。无需因此关闭其他托盘功能。
