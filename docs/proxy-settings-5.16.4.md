# 5.16.4：代理设置

设置窗口左侧“应用”分组增加“代理设置”。旧配置没有 `proxy` 字段时，默认跟随系统代理，保留 5.16.3 的网络行为。

| 连接方式 | 行为 |
| --- | --- |
| 跟随系统代理 | 读取 Windows 的共享手动代理地址；代理环境变量优先，并沿用环境变量的绕过规则。 |
| 直接连接 | 忽略系统及环境变量代理，直接连接目标服务。 |
| 手动代理 | 使用本页填写的协议、服务器与端口；覆盖系统与环境变量设置。 |

手动模式支持 HTTP、HTTPS 和 SOCKS5。服务器填写 IP 或域名，不包含协议、端口或用户名；IPv6 可填写 `::1` 或 `[::1]`。端口范围为 1–65535。多数本机代理软件选择 HTTP，HTTPS 表示与代理服务器本身建立加密连接；它与目标天气服务使用 HTTPS 是两回事。SOCKS5 将目标域名交给代理解析。

例如代理软件提供 `127.0.0.1:7890` 的 HTTP 端口：选择“手动代理 → HTTP”，服务器填写 `127.0.0.1`，端口填写 `7890`。切换连接方式会保留手动输入，切换页面保留草稿；点击“保存设置”才写入配置。

“测试连接”在后台检查当前选择能否取得 Open-Meteo 的有效温度数据，显示耗时或失败原因。测试不会保存设置，也不会改变天气来源或更新天气缓存。测试中可继续编辑、切换页面；输入变更后忽略旧结果并提示重新测试。

保存后，天气及预报、城市搜索与公网 IP 定位、节假日数据更新、版本检查、Microsoft 符号下载均使用所选连接方式。运行中的旧天气请求若使用了此前的代理配置，其结果不会显示，完成后会用新配置重新请求。天气来源仍按原顺序回退；某个来源不提供体感温度时，继续按原规则显示 `—`。

系统模式沿用 ureq 的 Windows 共享手动代理支持；PAC、按协议分别配置的 Windows 代理和手动代理认证未在本页新增。

## 配置格式

```json
{
  "proxy": {
    "mode": "manual",
    "protocol": "http",
    "host": "127.0.0.1",
    "port": 7890
  }
}
```

`mode` 为 `system`、`direct` 或 `manual`；`protocol` 为 `http`、`https` 或 `socks5`。完整配置位于 `%LOCALAPPDATA%\LiteTray\config.json`。

## 验证方式

网络回归用本地模拟代理检查真实的 HTTP CONNECT、HTTPS 代理 TLS 和 SOCKS5 域名握手，并验证直连绕过系统及环境变量代理。设置页回归通过真实原生通知、页面导航和保存验证草稿保留、错误输入拒绝、后台测试无保存副作用及旧结果丢弃。测试中的注册表与环境变量修改在隔离子进程执行，原生设置控件位于非输入桌面。

本补丁只重建宿主，沿用哈希一致的 5.16.2 发布版任务栏适配和弹窗钩子 DLL。安装仍保留用户配置、日程与缓存，继承 5.16.3 的开机启动路径修复。
