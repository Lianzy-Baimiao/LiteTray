# LiteTray 产品与实现规格

状态：2026-11-06 已按用户要求转为 Rust 开发。当前交付与验证状态以 README 和 progress.md 为准；本文件保留完整原生任务栏接管的验收要求。

## 1. 产品目标与验收边界

让用户在所有或指定显示器上使用原生托盘、控制中心和可定制时钟，点击时钟即在该显示器打开日历和天气面板。日常不依赖 Windhawk 运行。

必须保留原生托盘图标的实际交互。仅在屏幕右下角覆盖一个时钟窗口，或绘制一排不可操作的托盘图标，不满足完整替代的验收要求。

“先实现当前使用的功能”是交付顺序，不是删除另外两个模块已有能力。全量迁移覆盖情况必须逐项记录，未支持的格式字段要显示迁移提示，不能静默忽略。

## 2. 功能范围

| 能力 | 第一轮可用版本 | 后续兼容工作 |
| --- | --- | --- |
| 多屏托盘 | 所有/指定显示器，原生图标和隐藏图标入口 | 部分系统图标的既有上游限制单独验证 |
| 控制中心 | 网络/音量/电池入口，弹窗定位于点击屏幕 | 触摸/笔输入、异常缩放组合 |
| 原生交互 | 左键、双击、右键菜单、动态新增/删除、overflow | 拖放重排和复杂第三方应用回调 |
| 时钟 | 当前两行格式、秒、星期、字体、字号、颜色、对齐、tooltip | 多时区、ISO 周数、其他格式兼容 |
| 日历面板 | 月视图、切月、选日期、返回今天、可选农历 | 节气、法定节假日与调休；需要独立可靠数据源 |
| 天气 | 迁移现有城市、当前天气、更新时间、离线缓存 | 小时/多日预报、数据源切换、空气质量 |
| 扩展内容 | 面板内置可选区域，默认只启用日历和天气 | 网速、硬件指标、媒体信息、日程源 |
| 系统行为 | 多 DPI、自动隐藏、休眠恢复、Explorer 重启后恢复 | 更广的 Windows 版本矩阵 |

后续兼容项未验收前，只能发布带明确限制的预览版，不能标记“两模块全功能兼容”。不把日程同步或账号登录作为第一版依赖。

## 3. 默认交互

- 第一行沿用 `yyyy/MM/dd dddd  HH:mm:ss`，第二行显示现有城市的天气摘要。
- 左键时钟：切换日历/天气面板；面板贴近点击时钟，在当前显示器工作区内定位。
- 再次点击、Esc、点击外部：关闭面板。正确处理点击转发，防止先关闭又被同一事件重新打开。
- 右键时钟：打开设置、复制时间、打开系统通知面板、退出。系统通知入口仍可到达。
- 系统通知按钮与时钟的输入区域分开识别；不笼统拦截整个 notification/date-time 按钮。
- 日历切换只更新日期选择，天气始终说明其真实观测时间，不随所选历史日期伪造天气。
- 启用农历时本地计算；法定节假日和调休不能仅由农历规则推断。
- 天气失败显示最后成功数据、时间和过期状态；首次失败显示暂无数据，禁止显示虚构实况。
- 设置即时预览并可恢复默认；首次导入显示可迁移/暂不支持清单。

## 4. 实现决策

已决定使用 Rust + Win32，系统能力通过 windows-sys/windows 访问，后续适配层也以 Rust DLL 实现。设置页与日历优先使用原生控件，任务栏内部 COM/WinRT 调用封装在独立适配层。原生绘制同时需要补齐键盘操作和 UI Automation 可访问性。

结构：

```text
LiteTray.exe（普通用户会话）
  ├─ 配置、单实例、生命周期与按需设置窗口
  ├─ 日期/时区格式化、农历、天气服务与缓存
  ├─ 原生面板窗口（关闭时停止绘制与动画）
  └─ 受限 IPC
       ├─ explorer.exe 中的任务栏适配 DLL
       └─ 必要时 ShellHost.exe 中的弹窗定位适配 DLL
```

这里的 DLL 属于独立软件自身。目标是去除 Windhawk 运行依赖，并保留完成原生托盘功能所必需的进程内适配能力。

### 宿主与适配层的边界

- 宿主生成已格式化文本和样式快照；适配层在正确的任务栏线程更新 XAML。
- 适配层报告时钟点击、窗口矩形、显示器与 DPI，宿主负责弹窗。
- 天气 HTTP、JSON 解析、磁盘写入、复杂日期计算不在 Explorer 的 UI 线程执行。
- IPC 使用版本化消息、长度限制、用户 SID 限制和不可重入的异步投递。宿主失联时不阻塞任务栏。
- 首轮采用宿主加 DLL，无常驻系统服务。接入方式、跨会话行为和进程重启恢复须在技术验证中落地，不能把“仅一个 EXE”当成既定承诺。

### 任务栏适配

- 用编译后随包提供的 DLL 与专用 hook 设施替代 Windhawk 运行时编译和通用模块管理。
- 首先针对当前 26300.9711 build 验证，再增加明确的系统模块版本适配；不使用一组固定内存偏移支持所有 Windows。
- 若解析内部符号，按系统模块身份/PDB 签名缓存结果；下载和解析不阻塞 UI。缓存不匹配不得继续使用。
- 对关键符号、对象布局与 XAML 元素进行一致性检查；安装 hook 应可回滚，避免只安装一半。
- 缺少支持时保留系统行为，并在设置中给出功能不可用原因。
- 共享原生模型不代表可随意跨 XamlRoot 使用同一视觉元素；菜单、内容所有权与坐标转换需要单独处理。
- 显示器用稳定设备路径保存偏好，运行时解析到当前 HMONITOR；不能长期保存当前枚举序号。
- 退出恢复原绑定、尺寸、可见性、布局和输入处理；与其他模块共存时避免覆盖后来发生的改动。
- 注销/退出和 Explorer 崩溃不能完全等价处理；连续失败要停止重新接入，防止重启循环。

### 日历与天气

- 原生面板按需创建；可缓存轻量模型，空闲时不持续刷新布局。
- 保留现有 wttr.in 城市和十分钟刷新习惯，具体请求与返回格式单独实现、校验。
- 异步请求、超时、响应体限制、失败退避和最后成功数据缓存必须具备。
- 后续更换天气供应商时对数据模型适配，不把特定服务返回字段嵌进视图。
- 默认手动城市，迁移现有配置即可使用；不需要新增自动定位。
- 天气供应商可用性、额度和发布许可需要在实际接入时核对。原型中的预报为示例，不是服务能力验证。
- 农历/时区计算使用明确支持范围的库或系统能力，分别覆盖闰月、年界、闰年和夏令时场景。

## 5. 开源代码复用

Taskbar multi-tray 为 MIT，可在保留声明的条件下移植，但需要替换 Windhawk 提供的 hook、符号解析、设置和生命周期。

Taskbar Clock Customization 源码声明 GPL v3。若基于其代码改编发布，应采用相应 GPL 合规方案；若希望另选许可证，则独立实现必要的时钟格式和 UI，不直接搬用该实现。当前规格与配置导出不决定最终产品许可证，也没有把上游代码纳入工程。

具体依赖（hook 库、日期库、天气 SDK 等）在选型时记录版本及许可证。进程隔离不是绕过开源许可的依据。

## 6. 性能验收

以下是工程目标，尚未测得：面板关闭时宿主私有内存争取控制在 30 MB 内，空闲 CPU 长时间接近 0，关闭秒显示时按分钟边界更新。显示秒时只每秒更新所需文本；天气每十分钟更新，不使用高频轮询检测窗口。

正式报告必须同时给出：

1. 面板关闭/打开的宿主私有字节、工作集和句柄数。
2. Explorer 与 ShellHost 的内存、CPU 增量，而非只报告 LiteTray.exe。
3. 相同功能和显示器配置下，Windhawk 配置窗口关闭后的基线。
4. 秒开/关各至少五分钟的 CPU、唤醒与内存数据，热启动与冷启动分开。
5. 连续运行、反复开关面板和显示器热插拔后的资源回收。

只有相同口径的 A/B 数据才能支持“更轻”的结论。

## 7. 开发顺序与完成条件

### A：原生接入技术验证

在当前 build 完成时钟定位、样式/文本修改、点击坐标转发与恢复；实现针对 Explorer 重启的重新连接。证明可以脱离 Windhawk 运行。测试前导出现有配置，仅对重叠的两个模块安排切换。

完成条件：主屏和副屏能分别识别时钟，适配退出后恢复，关键能力缺失时不破坏系统任务栏。此阶段不能宣称多托盘替代已经完成。

### B：多屏托盘闭环

实现选择显示器、原生绑定、隐藏图标与控制中心、副屏坐标修正、右键菜单和拖放。接入设置后验证监视器热插拔与 DPI 变化。

完成条件：不同副屏上的真实应用托盘回调、上下文菜单和控制中心在正确屏幕工作；原生主屏交互不回归；已知不支持项有明确记录。

### C：时钟、日历、天气闭环

实现当前两行配置迁移、字体样式、原生日历面板、天气缓存和失败提示。处理通知入口、键盘与焦点，加入可用的设置窗口。

完成条件：用户不依赖 Windhawk 即可完成当前两模块的日常使用路径，实时天气与缓存状态有清晰区分。

### D：性能、兼容与发布

完成同口径性能对比、配置回退、系统版本兼容矩阵、连续故障停用、可选开机启动和卸载恢复。再逐步扩充原模块其余模板变量。

## 8. 必要验证场景

- 单屏/多屏、主副屏互换、显示器位于左侧或上方（负坐标）。
- 100%/125%/150%/200% 混合 DPI、分辨率变化和显示器断连。
- 自动隐藏任务栏、全屏应用、远程会话、显示器睡眠与系统恢复。
- Explorer 重启、ShellHost 重启、宿主退出/崩溃和无天气网络。
- 托盘 app 增删、单击/双击/右击、隐藏区、拖放、管理员应用托盘回调。
- 当前其他任务栏 Windhawk 模块的共存；重叠功能不得由两个实现同时接管。
- Windows build 未支持、符号缓存损坏和部分 hook 安装失败。
- 日期跨月/跨年/闰日、时区切换、系统时间修改、秒显示与多行宽度。

## 9. 下一步需要落地的技术证据

本机调查证明了现有配置和上游路径；没有证明独立注入、hook 替换或 26300.9711 上的独立适配已成功。原生接入验证是下一阶段第一优先级，比先扩展大量面板小部件更能决定项目能否真正替代现有方案。
