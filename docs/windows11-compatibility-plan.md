# Windows 11 跨版本任务栏接管方案

日期：2026-11-09。状态：第 0 阶段已实施于 5.13.0；5.13.2 新增 26300.9818 x64 模块资料并通过 Sandbox 的真实主屏接管与恢复检查，同时保留 26300.9711 资料；5.14.0 增加独立兼容性页签和带验收边界的只读目录，并在独立 Windows 11 Pro 25H2 客体完成单屏限定验收后纳入 26200.8457 精确资料。第 1 阶段要求的主副屏完整功能矩阵仍未完成。当前范围见 [兼容检查说明](compatibility.md)，运行证据见 [9818 兼容记录](compatibility-9818.md) 和 [25H2 兼容记录](compatibility-8457.md)。

5.14.1 继续以两个独立安装客体验证 25H2 `26200.8037` 与 Enterprise LTSC 2024 Evaluation `26100.1742`，将默认精确模块目录扩展到五组。LTSC 的字段偏移与较新 25H2 不同，已通过独立符号、指令和实际对象读回核验；共用的是已实现的接口方案。两组仅登记模块/布局、单屏时钟文字与宽度更新/恢复、托盘准备/停止三个场景。逐轮失败、lab 与正式构建证据见 [新版本记录](compatibility-next-versions.md)。

5.14.2 实现 22H2 / 23H2 的四参数借用对象坐标入口，在独立安装的 Pro `22621.1702` 和 `22631.2861` 客体通过六项检查及原始恢复独立复核后，将两套精确资料加入默认目录，共七组。实际安装映像复用已验证的 source 与时钟拓扑，托盘 ABI 单独实现；早期 BASE 模块研究不能代替这些实际映像的证据。[22H2 / 23H2 记录](compatibility-22h2-23h2.md)分别记录模块、所测程序和验收范围。

目标是在 Windows 11 各代原生任务栏上，提供原位时钟、点击日历、滚轮音量和完整的多屏托盘交互。覆盖情况分别记录到系统架构、模块版本、功能和实测场景；未来尚未验证的累计更新不自动标为支持。

目前默认内置七组精确 x64 模块：26300.9711、26300.9818、26200.8457、26200.8037、LTSC 26100.1742、22H2 22621.1702 与 23H2 22631.2861。9711 保留更新前的主副屏基线；其余六组分别在单显示器 Sandbox 或独立安装虚拟机中验证主屏时钟文字/宽度更新、停止恢复及托盘入口准备/停止。普通 Pro 24H2 也已完成独立客体复测；5.15.2 在 24H2/25H2 验证真实分辨率变化恢复，并在 25H2 验证虚拟双屏停用、恢复后的自动重新连接。完整输入、托盘交互和混合 DPI 矩阵仍待补齐。集中资料、离线报告、按模块实现组合和时钟/托盘能力协商均已实施；下文源码限制表保留重构前基线。现有验收见[补充记录](compatibility-completion-5.15.1.md)，21H2、26H1 和 ARM64 的补齐依据见[后续覆盖研究](windows11-coverage-next-research.md)。

## 一、采用的路线

将目前的单版本适配扩展为 **按任务栏实现分代、按模块身份解析、按功能验证** 的兼容模块。

- 复用现有 EXE、日历、天气、日程与 `taskbar_service` 生命周期。
- 把系统 DLL 身份、私有入口、对象字段和控件拓扑规则集中管理；界面和业务逻辑不再知道这些细节。
- 系统版本号用于展示，不代替模块匹配。当前按 `taskbar.dll` 完整 PE/PDB 身份唯一选择内置资料，磁盘检查再验证 SHA-256；shell、tray 和运行时检查始终使用同一份资料。身份未知、歧义或哈希不符不回退到旧版本。
- 时钟、时钟输入、托盘模型复制、跨屏交互分别给出支持结果。展示图标但无法正常点击、悬停或打开菜单，不能标为“托盘复制可用”。
- 保留 9711 资料；9818、8457 使用从各自映像/PDB 重新核验的地址、字段和 ABI，复用已证明一致的解析方案。8457 的托盘载体为 `Taskbar.View.dll`，9711/9818 为 `SystemTray.dll`；出现实际结构差异后，再增加或拆分对应实现。

## 二、代码中的实际限制

重构前基线：`f9a57fd`。下面列出当时的源码限制和改造方向，不表示当前仍只有一份固定模块资料，也不是跨版本测试结果。集中资料和七组模块的唯一选择已完成；七组复用经各自证据核验的 source 和拓扑，托盘分为三参数按值与四参数借用两种 ABI 实现，具体字段、地址及映像身份各自独立。

| 位置 | 基线限制 | 改造方向 |
| --- | --- | --- |
| [`taskbar_clock::preflight`](../src/platform/taskbar_clock.rs) 与 [协议常量](../crates/adapter-protocol/src/taskbar.rs) | `taskbar.dll`、`twinui.pcshell.dll` 各固定一个完整哈希 | 移入明确的兼容资料，仍核对实际模块；不通过删除哈希检查来扩大支持 |
| [`taskbar_source`](../crates/taskbar-adapter/src/taskbar_source.rs) | 固定 `TaskbarHost +0x38`、子接口 `+0x10`、具体 vtable RVA `7739040` 和内存 PE/PDB 身份 | 定义经验证的 source 解析方案及其 ABI，符号/反汇编证据与模块绑定 |
| [`tray_symbols`](../crates/taskbar-adapter/src/tray_symbols.rs) | `SystemTray.dll` 固定哈希、三个 RVA 和函数前导字节 | 按匹配 PDB 解析三类坐标入口，校验签名类别与代码；不同 ABI 使用独立 Rust 实现 |
| 同一模块选择流程 | 只在 `SystemTray.dll` 中找托盘坐标入口 | 上游已有 `Taskbar.View.dll`、`SystemTray.dll`、更早时钟 `ExplorerExtensions.dll` 的变体；检测实际加载模块和功能开关形态，不按名称移植同一个 ABI |
| [`symbols`](../src/platform/symbols.rs) 与 [`HostLayout`](../crates/adapter-protocol/src/lib.rs) | 已有 PDB 下载缓存、GUID/age 核验和六个符号角色；字段解析仅接受一种短 x64 指令布局 | 扩展为有界的符号角色与解析方案；识别有证据的变体，不靠宽泛字节搜索和猜偏移 |
| [`discovery`](../crates/taskbar-adapter/src/discovery.rs) 与 [`topology`](../crates/adapter-protocol/src/topology.rs) | 固定 `SystemTrayFrame → SystemTrayFrameGrid`，角色名、日期时间控件和类型 | 增加经实际快照核验的拓扑方案，保留唯一性、类型、父子关系和 XamlRoot 检查 |
| [`taskbar::prepare`](../crates/taskbar-adapter/src/taskbar.rs) | 托盘交互准备失败，会使同一接管请求失败；多屏路由要求同一线程 | 在进入写入阶段前协商功能，必要时按线程组织会话；不把跨线程 COM 对象直接交给现有流程 |
| [`diagnostics`](../src/platform/diagnostics.rs) | 用 `build >= 22000` 直接标记“XAML 任务栏” | 检测实际窗口、模块和运行时实现；Windows 11 版本号不能证明托盘就是某一种结构 |
| [Windows CI](../.github/workflows/ci.yml) | 一种托管 runner 上编译、测试和自建 XAML 宿主 | 保留此层，再增加真实 Windows 11 的交互会话验收 |

现有 `Backend::prepare/connect` 和 `Session::update/stop/take_activation` 已有合适的调用位置，无须把版本分支散落到 UI。保留来源窗口、PID/TID、XamlRoot、对象生命期检查和停止恢复语义。

## 三、兼容模块的输入与结果

无 Windows 调用的共享资料模块已经实施，由宿主与 Explorer 适配器共同使用。当前磁盘报告提供选中资料、各模块及各功能的检查状态；未匹配唯一资料时 `profile_id=null` 并给出原因。下列是后续跨分支和能力协商的目标数据形状，其中“已实测”等证据等级并非当前磁盘报告已经提供的运行时结论：

```text
SystemSnapshot
  架构、系统版本（展示用途）、任务栏实现
  各相关模块：实际路径、SHA-256、PE 身份、PDB GUID+age

CompatibilityProfile
  资料版本、适用模块身份、最低适配器协议版本
  已实现的 source 解析方案编号、拓扑方案编号
  必需/可选符号角色、各钩子的已知 ABI 类别
  各功能的证据等级和验收记录

CompatibilityReport
  每项功能：已实测 / 结构检查通过但待实测 / 不支持 / 暂未就绪
  原因、选中资料、缺失模块或符号、允许尝试的恢复动作

ResolvedLayout
  经验证的模块身份、RVA、节区、前导字节、解析结果
  仅在本次进程/模块身份一致时交给对应线程使用
```

`ResolvedLayout` 不含可跨进程复用的原始 COM 指针。不把外部 JSON 解释为任意指令或任意内存读写程序。解析方案和函数签名实现编译在 Rust 代码中；数据只能选择已实现方案并提供有界参数。

5.14.0 在此基础上增加展示层：`support_catalog()` 从已编译资料生成精确模块目录，附带解析方案和逐场景的 `tested`、`historical`、`not_run` 记录；`Report::summary()` 只投影本次磁盘结果，不把历史实测转换为当前运行时能力。验收元数据绑定资料 ID 与三个模块哈希，新增或更换映像默认无完整验收。8457 通过有记录的限定场景后加入默认资料，唯一选择和 preflight 安全策略继续适用。

设置中的“兼容性”页在工作线程读取系统标签、构建号/UBR、架构及磁盘报告，分别显示当前检测和已有证据。它不访问 Explorer、不下载符号、不修改配置。报告导出保存页面快照及其检测时间；系统版本标签与相同解析方案仅说明环境和共性，不提供跳过精确模块检查的入口。

功能依赖按最小集合校验：

- **时钟文字与样式**：可靠的 source、时钟拓扑、可恢复的属性写入。
- **时钟交互**：上述条件加独立点击区域、系统日历事件抑制、鼠标/触摸/键盘路由。通知铃铛区域不随时钟一起拦截。
- **完整托盘复制**：主副屏模型、图标状态同步、坐标换算、点击回调、悬停与菜单都通过。
- **系统区域复制**：网络、音量、隐私状态、控制中心等分别验证，不能因为普通第三方图标可复制就视为全部可复制。

例如托盘坐标入口尚不支持、时钟路径已核验时，可以继续提供时钟。若 source 本身无法证明，所有依赖它的功能停止接管，原生日历/托盘保持可用，LiteTray 自己的日历和设置仍可打开。状态页应准确说明当前可用功能。

## 四、符号、离线使用和系统更新

1. **生产启动使用随程序发布的已验证资料。** 当前七组资料编译进程序，以精确模块身份选择；旧资料不能匹配新模块。生产路径不读取外部符号映射或任意 JSON 覆盖，已支持模块无需用户下载 PDB。
2. **开发侧解析新模块的匹配符号。** 使用微软公开符号服务器，在独立辅助进程完成 DbgHelp 和必要的反汇编，生成资料前核对模块/PDB 身份、字段和 ABI。当前 `--prepare-symbols` 仅保留为开发分析工具；生产 `preflight` 读取所选内置布局，不下载 PDB、不调用 DbgHelp。9818、8457 已按这一流程取得各自符号和反汇编证据；通用离线工具输出仍为待人工审阅及客体验证的候选。
3. **PDB 匹配只证明符号来源。** 它不自动证明 C++ 对象字段、生命周期、函数签名和系统菜单行为。候选布局还须通过已实现解析规则、模块节区/入口检查、唯一 source/root/window 归属验证。
4. **分清检查成功与验收成功。** 新补丁只通过结构检查时标为“待验证”，先在测试环境通过功能矩阵。默认不会把相同 24H2/25H2/26H2 标签当成所有月更都已支持。
5. **后续资料获取工具的失败应可理解、可恢复。** 若加入自动下载，应区分离线、404、超时、符号缺失、身份不符和缓存损坏；损坏缓存只作隔离并有界重试。当前生产启动不依赖此类下载，开发解析失败也不能把未经验证的结果带入运行时。
6. **更新资料可独立于业务更新。** 初期内置已验证资料即可。后续可从公开 Releases 分发签名的有界资料包，客户端用内置公钥验证来源与完整性，无需用户填写 API Key；新 ABI 仍需软件升级。不得静默下载并执行未知 DLL 或脚本。
7. **关注更新后的磁盘/内存不一致。** 模块文件已更新但 Explorer 仍使用旧映像时，以实际加载身份为准并核对对应资料；不能用新文件地址布局处理旧的内存对象，也不能只验证文件路径。

这样常驻部分仍是轻量 EXE 和必要的原生适配器；下载器、符号解析器不常驻，不增加通用插件运行时。

## 五、两条需要验证的发现路径

**主路径：扩展现有符号与宿主解析。** 已有大量生命周期、属性恢复和点击处理可以复用，优先解决 `taskbar.dll` / `twinui.pcshell.dll` / `SystemTray.dll` 的硬编码。不同月份共享解析方案，解析结果仍对应各自的精确模块身份。

上游显示相关代码在 `ExplorerExtensions.dll`、`Taskbar.View.dll`、`SystemTray.dll` 中存在不同代的实现，且部分类型由功能开关分批启用。资料必须能描述不同模块角色，不能把当前三个 DLL 名字永久固化成所有 Windows 11 的前提。早期托盘的时钟区域与图标区域也可能走不同实现。

**小范围技术验证：XAML Diagnostics。** 调研它是否能在至少两代真实任务栏上获取根、找到所属 HWND、接收树更新，从而减少对 `TaskbarHost` 内部字段的依赖。必须验证启动/退出、CPU/内存开销、树重建、与已有诊断工具共存，以及 System XAML 和 WinUI 3 的差异。拥有公开的诊断接口不等于获得官方“替换系统任务栏”扩展契约；它也不能单独解决托盘数据模型、回调和菜单定位。如果验证没有明显降低私有依赖，继续现有主路径。

早期非 XAML 托盘单独实现发现、文字绘制和交互适配，使用同一宿主生命周期。后期 System XAML、可能出现的其他 XAML 宿主，也不能把接口指针强转成当前 ABI。先记录运行时差异，再决定需要几份实现。

ARM64 另设里程碑。当前协议、指令解析和钩子实现明确依赖 x64，x64 仿真程序不能直接把 x64 DLL 接入原生 ARM64 Explorer。需原生构建、适用的挂钩实现、结构/调用约定验证和真机验收。

## 六、落地顺序与退出条件

| 阶段 | 工作 | 完成标准 |

| 0：基线与报告 | 将现有 26300.9711 资料集中管理；增加只收集模块/版本信息的报告，区分不注入的磁盘检测与进入 Explorer 的只读探测 | 当前版本行为不变；未知模块不写入；损坏资料可解释；现有测试通过 |

| 2：现代正式分支矩阵 | 依官方版本表覆盖 24H2、25H2、26H2 等实际目标；增加各分支不同累计更新和功能形态 | 发布明确的“模块/补丁 × 功能”支持表，新补丁有可重复的新增资料流程 |
| 3：早期与特殊分支 | 覆盖 21H2、22H2、23H2 的真实托盘形态；26H1、新设备和 ARM64 分开验证 | 每种新实现独立通过验收，未通过的范围保留清晰状态 |
| 持续维护 | 累计更新、预览分支、新 XAML 宿主、资料撤回和回归 | 新资料有证据；不兼容时只停用受影响功能且确认原生状态恢复 |

当前进度：第 0 阶段已完成；9818 和独立 25H2 8457 的真实主屏验收均属于第 1 阶段进展，尚不满足该阶段全部退出条件。9818 单显示器 Sandbox 中，基线四项命令均 exit 0、原生 XAML 164 项、应用进程内私有 Shell source 6 项通过；真实时钟宽度从 240 更新至 320，停止后恢复原文字、宽度和可见性，Explorer PID/TID 与任务栏 HWND 不变；5 类必需托盘区域及坐标入口完成准备/停止，未启用托盘复制。实际日历点击、滚轮音量、托盘复制及菜单/悬停和多屏矩阵仍待验收，详见 [9818 兼容记录](compatibility-9818.md)。

该 Sandbox 来宾显示 Enterprise 24H2 `26100.9818`，三份关键模块却与宿主 26H2 `26300.9818` 相同；不能据此另计一份独立 24H2 镜像或正式分支覆盖。

5.14.0 的页签和证据目录已补齐用户查看入口。独立安装的 Windows 11 Pro 25H2 `26200.8457` 客体使用另一套真实模块，已通过相同隔离基线、私有宿主和真实主屏检查；三帧文字更新、55→240→320→55 宽度变化及停止恢复均被读回，托盘准备/停止通过且复制未激活。冻结 lab 包验证后，该精确资料加入默认目录；默认 release 构建又以自己的二进制和 71 文件清单完成六项复测。两种构建及最终文档打包的清单边界见 [25H2 记录](compatibility-8457.md)。该结果不满足完整输入与主副屏矩阵，不能把第 1 阶段标为完成。

下一步在已有独立 25H2 客体补齐日历、滚轮、菜单/悬停、托盘复制、多显示器和 DPI 场景，并扩展到其他独立系统分支及累计更新。后台虚拟机仍须保留已登录桌面，测试 helper 应核验为与 Explorer 一致的普通用户 Medium 完整性；首次登录 bootstrap 的提升权限曾影响排查，不能只凭 session 与桌面相同就忽略令牌差异。普通目录里放几个其他版本 DLL 不能代替该系统真实任务栏。

按本次取回的 [微软版本资料](windows11-compatibility-research.md)，构建家族为 21H2/22000、22H2/22621、23H2/22631、24H2/26100、25H2/26200、26H2/26300，以及面向新设备的 26H1/28000。该清单用于组织测试镜像，不用作函数地址或控件结构判断。已停止维护的历史版本仍可作为完整覆盖目标，优先级低于当前使用的正式分支；LTSC 另记版本、架构和实测结果。

不把 ExplorerPatcher、StartAllBack 等替换任务栏纳入“原生 Windows 11 已支持”的含义。检测到替换实现后单独分类，经过测试再决定是否增加独立适配，不修改其他工具配置。

## 七、验收、故障与性能

测试分层：

- **离线解析**：真实模块提取的身份/符号/指令夹具；身份不符、重复符号、未知指令、缺失模块、ABI 不符、损坏缓存和资料版本不符都能拒绝。公开仓库保留最小必要证据，不打包整个 Windows DLL/PDB。
- **自有进程原生检查**：沿用 XAML 属性、绑定、输入、恢复、生命周期和界面测试，检查协议升级兼容与失败路径。
- **真实 Windows 11 交互桌面**：版本虚拟机中使用快照和至少两块虚拟显示器。可在后台运行虚拟机；系统任务栏验收本身需要已登录的交互桌面，纯无桌面 CI 不能替代。

每个正式兼容档案至少覆盖：

1. 主屏/副屏、普通/小型任务栏、单行/双行、100%/125%/150%/200% 缩放及混合 DPI、负坐标和自动隐藏。
2. 时钟连续点击、第一次点击、外部点击收起、分离窗口；点击通知铃铛和有/无系统通知；滚轮音量与中键静音不打开日历；鼠标、触摸和键盘操作。
3. 图标新增/删除、显隐/顺序变化；每屏点击与右键；首次及重复悬停、菜单定位、快速跨屏切换；QQ 的额外实验弹窗路径独立记录。
4. 任务栏右键、主题切换、显示器插拔、DPI 改变、Explorer 重启、锁屏/恢复、睡眠/唤醒和系统更新后的重新连接。
5. 正常退出和宿主异常退出后的文字/绑定/菜单/事件恢复；中途连接失败不遗留一半钩子；已安装的钩子不能仅因参数数量相同就视为同一 ABI。

已有“Windows 通知存在时点击可能崩溃”的反馈必须纳入基线排查，不能随着支持范围扩大被掩盖。当前未复现不等于已修复。

Explorer 进程内的 ABI 错误、访问违例、fail-fast 无法由外部守护逻辑保证挽救。应在实验虚拟机中先测，按资料/模块身份记录失败，并抑制连续失败后的自动重连；显式系统重启和用户重启 Explorer 不能直接当作适配器崩溃证据。现有进程内三次失败暂停规则可复用，但跨重启熔断需要单独设计持久状态。

每版记录首次连接耗时、缓存命中连接耗时、日历首次打开耗时、空闲 CPU/工作集以及树变化时开销。跨版本工作不能把 PDB 下载、全树扫描或重建设置窗口塞进时钟点击路径；UI 闪烁和卡顿也属于验收失败。

## 八、下一项具体实现

当前交付内容是七份精确资料，以完整模块身份和 SHA-256 选择一致布局，并提供兼容性页签、不注入的分功能磁盘导出和运行时独立核验。页面把当前磁盘匹配与既有验收范围分开；新增资料的地址、字段与 ABI 分别有匹配符号/反汇编依据，单屏主时钟更新/恢复和托盘准备/停止已有 Sandbox 或独立虚拟机结果。共性和差异汇总于 [模块对照](windows11-commonality.md)、[8037 / LTSC 验证记录](compatibility-next-versions.md)与 [22H2 / 23H2 记录](compatibility-22h2-23h2.md)。

下一项验收是补齐已登记资料的日历点击、滚轮音量、菜单/悬停和主副屏场景，逐项完成第 1 阶段矩阵，并增加其他独立分支的真实 Explorer 测试。自动能力协商、其他任务栏分代所需解析方案和在线兼容包仍待实施；当前七组模块支持不能扩大为 Windows 11 全版本支持。
