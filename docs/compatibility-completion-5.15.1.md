## 显示变化测试方法

现有 `std VGA + Microsoft BasicDisplay` 客体是单显示器环境。Windows viogpudo 驱动实现也只支持单个显示源，给单张虚拟显卡设置多个输出不等于 Windows 实际获得双屏。多屏候选使用独立虚拟显卡，并要求 Windows 枚举出实际活动显示器、桌面坐标和对应任务栏后才进入产品验收。

单独的分辨率恢复脚本运行真实后台应用，使用普通用户与独立配置目录，实际调用 `ChangeDisplaySettingsEx` 切换并恢复驱动公布的模式。脚本观察操作系统产生的 `WM_DISPLAYCHANGE`、原会话恢复、重新连接以及实际时钟文字与宽度，并在结束时请求应用正常退出、核对原显示模式与 Explorer 连续性。它不发送合成显示变化消息，不把分辨率变化称为显示器插拔或混合 DPI 测试。

恢复后的时间文字可能正常跨分钟变化，因此单独保留“原生文字完全相等”观察值；结构恢复要求控件类型、可见性、高度、容器宽度一致，且没有遗留测试文字。该范围不同于短时主屏检查中的完整原字段相等证明。

## 实际双屏停用与恢复

25H2 客体增加一张独立 virtio 显卡，通过 Windows 正常安装已签名的 viogpudo 驱动。实际枚举得到两块 `1024×768 / 96 DPI` 显示器，主屏位于 `(0,0)`，副屏位于 `(1024,0)`，分别存在主、副任务栏。单纯安装驱动和枚举双屏不计为产品通过。

先进行不运行 LiteTray 的环境验证。较新的虚拟模式查询返回了相互矛盾的路径标志与索引，因此第一版测试在写入前拒绝，没有猜解或改写驱动数据。标准 `QDC_ONLY_ACTIVE_PATHS` 查询返回合法的完整模式数组；独立候选保留这些数组及目标信号值，仅暂时停用唯一副屏路径。`SDC_VALIDATE` 分别确认停用和恢复可行，实际操作不使用 `SAVE_TO_DATABASE`、`ALLOW_CHANGES` 或合成显示通知。PowerShell 单项数组问题在执行前修正，旧候选与未执行记录保留。

环境运行 `sandbox-20261109-212520-0728bf91` 完成 Windows 实际显示器和任务栏数量 `2 → 1 → 2`，配置、源模式与显示矩形均恢复，Explorer PID 4172 和原主任务栏保持；副任务栏由 Windows 重新创建。归档 SHA-256 为 `555ac86f02fe5448661167923e595ec699031d6930c628e2d56a17546e29b37f`，78 项独立核验通过。

随后运行已发布 5.15.1 的真实后台服务，编号 `sandbox-20261109-214812-8643d285`，nonce `8a4272b1aef0432aa469d4745e05cd38`。服务 PID 5036 在两屏显示指定文字及 240 宽度，副屏停用后剩余一个时钟、恢复后再次出现两个时钟；两次均记录同一进程的真实 `WM_DISPLAYCHANGE → 恢复确认 → 重新连接`。正常 Exit 返回 0，原 Explorer、主任务栏及显示配置保持，两个原生时钟结构恢复。归档 SHA-256 为 `1b6d227194dce3ccfe84ef663ca901e71322ad0b52ec35e176d41c040af8b242`，204 项独立核验通过。
