## 任务栏接入实测

2026-11-06：`--probe-taskbar` 返回 Explorer 的相同进程/线程与两块屏幕任务栏信息；Explorer 启动时间未变，探测完成后模块枚举中没有 LiteTray DLL。没有修改现有 Windhawk 设置。`--prepare-symbols` 拒绝了不同版本的旧 PDB，下载匹配的 Microsoft PDB 后通过 GUID/age 校验，得到 GetTaskbarHost、FrameHeight、ITaskListWndSite vtable 等符号。该结果只证明接入和符号解析，不证明 XAML 接管完成。

后续补齐六个接口的精确 decorated name、RVA 所属节区权限、函数入口字节和 FrameHeight 字段偏移，当前磁盘模块可生成完整 `taskbar-layout.json`。测试覆盖截断 PE、越界 RVA、缺失/重复符号、数据节函数、模块哈希变化和未知指令布局。

一次后续 Explorer DLL 探测被执行环境自动审批拒绝，只有 `blocked by policy` 信息。此后没有重试或换方式接入 Explorer；当前新增的只读 XAML 检查仍未运行。全部新增写入验证都在独立 LiteTray 进程内完成。此限制不等于代码已通过/未通过任务栏兼容性测试。

## 长期会话的隔离验证

新增有身份、序号和超时限制的时钟命令，Prepared/Active/Restoring/Closed 生命周期，以及持有进程句柄的原生 UI 线程 watchdog。多组时钟作为一个会话更新和恢复；与其他写入发生冲突时停止会话并保留对方的新值或绑定。普通值未变化时跳过写入。

已验证：真实 Windows 计时器在测试接收窗口销毁后自动恢复；接收窗口和进程仍存活、没有心跳时，15 秒租期到期自动恢复；连续 12 次完整启停后，进程句柄数与 USER 对象数不增加。测试期间未查找或接入 Explorer。生产任务栏会话连接和实际 Explorer 环境下的崩溃恢复尚未验收，不能把这些检查称为已支持完整任务栏接管。

后续补齐独立 watchdog 窗口的原生命令接收，验证错误发送窗口、错误 nonce、重复命令、超大或无效消息被拒绝；跨线程更新仍在 XAML 所属线程执行。另启动同一 LiteTray 的隔离子进程，真实发送 WM_COPYDATA 更新两组 XAML 文本，再结束该测试子进程，验证持有的进程句柄和原生计时器驱动自动恢复。意外销毁 watchdog 窗口也恢复两组原值；已关闭会话拒绝延迟更新。这些端点尚未由真实任务栏创建。
