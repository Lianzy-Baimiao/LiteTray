## 点击订阅与时钟会话整合

Session 现在同时管理文字/样式和输入订阅。订阅在 Prepared 阶段保持停用，整组时钟更新成功后才启用；停止时先停用全部回调，再解除事件和恢复属性。部分订阅失败会回滚，重复时钟 ID、同一原生控件被重复使用会被拒绝。所有时钟共享递增点击序号，并阻止同步重入重复发出同一序号。watchdog 在发布前检查进程、接收窗口、租期及 Active 状态；使用弱引用避免会话与委托互相持有。

两个独立隐藏 XAML Island 的新增 10 项检查通过：准备阶段不拦截、共享序号与重入、显式停止、部分注册失败、租期过期、回调内停止、接收窗口消失、命令端点销毁、外部写入冲突，以及会话拥有者释放。测试保留原生委托至停止之后，再调用并确认不会继续消费输入。

独立预览也使用这套会话和 watchdog，心跳与设置对象的借用分离；宿主在原生调用期间保留组件引用，防止重入退出导致提前卸载。实机保持文件选择对话框打开超过 58 秒，取消后时钟仍显示当前时间且点击能展开日历，随后正常退出。此结果证明本进程路径整合，不代表真实 Explorer 接管或睡眠恢复已通过。

## 托盘模型共享事务

新增 `ModelLease`，按已验证的 source/target 和字段选择共享原生模型引用。先保存全部目标原值，读取并检查全部来源，再写入目标；首次来源为空时保持原界面，运行中来源显式清空则清除旧副本。相同模型引用跳过 setter，原生集合成员增删自然传播；watchdog 刷新处理集合对象替换和外部写入冲突。

两个独立隐藏 XAML island 已通过 18 个新增场景：同一集合进入两个目标、实时增删、来源替换/清空、旧集合脱离、Content/ItemsSource 绑定及 DataContext 继承恢复、Drop、首次写入前冲突、同文本的新绑定保留、可视 Content 和可视集合成员拒绝、513 项集合拒绝、重复/环形目标、组合字段与显式 null、与时钟/输入一起停止、超时恢复、启动失败回滚及跨功能对象重叠拒绝。原集合改变和原绑定源改变后，均检查目标仍按恢复后的规则更新。

通用依赖属性快照抽到 `property.rs`，时钟和托盘共用。首次写入也检查保存时的值/绑定身份；setter 返回后不再把当前值无条件认作自己写入的值，避免同步重入的外部写入被后续恢复覆盖。

追加回归检查覆盖已接管时钟的后续 setter 失败：Windows 保留旧值时仍保存原归属，能够完整恢复之前成功写入的属性。当前合计 79 个隔离场景通过。

该层仍只在 LiteTray 进程内运行。未完成真实任务栏控件匹配、系统托盘图标点击与菜单归属、overflow/控制中心/拖放和 Explorer 重连；模型引用正确不等于交互已经正确。集合检查是有界快照，无法在外部组件随后插入 UIElement 时预先拦截原生集合通知，真实适配必须验证系统来源的数据约定。

## 托盘结构识别与会话准备

新增严格的原生入口：XamlRoot.Content 直接子控件 `SystemTray.SystemTrayFrame` → 直接子控件 `SystemTrayFrameGrid`，不使用包含匹配或任意递归回退。容器内只按直接子控件角色匹配各托盘区域，内层 `SystemTray.StackListView` 不能重复或超出已知深度。只读检查响应附带带索引的独立 panel 快照、角色和具体失败原因。

时钟从通知中心或 SecondaryClockStack 内选择唯一可见的时间/日期 TextBlock，要求最小共同容器仅含两行文字和 Grid/StackPanel；通知按钮、铃铛或未知交互控件不能混入。面板外层祖先的可见性也参与判断。识别过程不订阅点击，因而不把整个 NotificationCenterButton 当作日历点击区。

原生 View 保存 COM 身份与至 XamlRoot 的父级链；生成 ClockLease 或模型 Pair 前再次核对。同名新控件、重命名、层级变化和脱离 root 均要求重新识别。模型配对要求不同 XamlRoot、选定区域齐全、原生接口对应且来源有非可视模型；不会共享可视 Content。当前严格核对完整 panel 快照，若准备期间图标列表变化也会要求重新识别，后续需要结合结构通知做重试。

新增 6 个结构单元测试与 9 个真实 XAML 隔离场景，合计 50/79 项通过。隔离场景从真实控件识别出两组时钟和三个模型区域，再实际启动同一 Session、停止并检查恢复；另检查名称/身份替换、重复角色、接口错配、外层隐藏和 root 脱离。夹具使用标准 Windows 控件，不伪装成 Explorer 私有 SystemTray 类；真实入口只验证拒绝不匹配框架，不能声称该机器的 SystemTray 树已验证。

加入祖先查询时曾在隔离进程发现错误 COM 接口指针导致退出，已修正为先 QueryInterface 到 IDependencyObject，再调用 VisualTreeHelper；完整检查重新通过。自检脚本现在在异常退出时保留退出码及日志目录。真实任务栏访问限制未变化，没有再次探测或接入 Explorer。

## 稳定的显示器选择

使用 `QueryDisplayConfig(QDC_ONLY_ACTIVE_PATHS)`、`DisplayConfigGetDeviceInfo` 和 `EnumDisplayMonitors` 读取活动物理目标与桌面区域。枚举前后核对设备映射，变化时有限重试；读取失败保留桌面枚举并报告原因，不从 DISPLAY 编号猜测设备。任务栏 HWND 只用于当次查询其所在屏幕，不保存句柄或显卡 source ID。

配置存储 Windows `monitorDevicePath`，按不区分 ASCII 大小写匹配；该标识不承诺跨接口更换、驱动重装或设备实例重建保持一致。旧 GDI 编号、离线及有歧义的设备保留为待匹配项。复制显示组共用一个桌面区域，只选部分物理目标时暂不选择该组并提示。偏好数量、长度、控制字符和重复项均有边界检查。

多屏页改用原生多选列表，支持鼠标、空格和手动刷新；显示设备通知经 500ms 合并后刷新。刷新与页面重绘保留未保存选择，已保存的顺序和大小写保持不变；只在明确保存时写入配置。设置摘要和导出诊断给出范围匹配、待匹配和警告信息。该解析尚未连接真实 Explorer 适配会话。

新增 5 项单元测试覆盖设备重编号/主屏变化、选择顺序与大小写、离线及旧编号保留、复制显示、歧义设备与非法列表项。当前 Windows 实际报告一块 HDMI 屏幕（2560×1600、主屏、DISPLAY2）和一个主任务栏，诊断映射一致。隔离配置下实测：空选择阻止保存、鼠标和空格切换、刷新保留草稿、保存前无提前写入、保存并重启恢复。再加入一个旧编号和一个合成离线标识，刷新及保存后文件仍按原顺序保留全部三项，最后正常退出测试实例。未进行真实硬件插拔或复制显示设置，也不把这些逻辑测试算作多屏实机验收。

API 参考：[QueryDisplayConfig](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-querydisplayconfig)、[DisplayConfigGetDeviceInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-displayconfiggetdeviceinfo)、[DISPLAYCONFIG_TARGET_DEVICE_NAME](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/ns-wingdi-displayconfig_target_device_name)。

## 范围计划、独立托盘与可见性事务

显示器解析结果现在接入 `routing::Plan`，按当前桌面设备匹配显式任务栏窗口，拒绝重复映射、缺失任务栏、缺少唯一主托盘来源和跨 UI 线程共享。来源按主任务栏角色确定，不使用枚举顺序；只选择副屏时允许读取主屏模型，但不修改未选中的主屏时钟。计划分别列出时钟、模型和可见性操作；主屏的已启用区域保留原来自然可见性，关闭区域才加入隐藏操作，“仅影响复制的副屏”跳过主屏组件规则。

原生准备器接收已验证窗口/root 对应的 View，核对窗口 PID/TID、完整路由记录和当前线程，再重新验证控件并捕获全部原值。三个独立 XAML island 实测只修改指定副本，其他两个根保持原样；绑定缺失/记录变化则在写入前拒绝。生产调用方仍须证明 HWND、XamlRoot 与当前屏幕实际对应，并处理活跃会话中的结构变化；当前隔离检查使用自己的窗口与逻辑屏幕标识，不代表真实多屏 HWND/root 映射已验收。计划没有接入 hook 启动路径，也未自动准备时钟输入订阅。

Session 现在允许没有时钟的准备状态，但无组件不能启动；独立托盘通过单独启动入口，不需要虚构时钟样式。它接受心跳和停止，拒绝 Tick/Update 且不提交该消息序号。可见性采用原生 Visibility 枚举依赖属性事务，恢复 binding/local/unset，纳入同一启动失败回滚、外部冲突停用、超时和退出生命周期。

## 运行中目标失效与恢复

范围会话新增 LeaseGuard：保留所用区域、内层列表、时钟节点及其祖先的 COM 身份和直接父级，同时保存实际 XamlRoot 对象与缩放。运行检查只读取这些节点、panel 的直接子区域及有界的独立时钟子树，不重新遍历所有生成的图标。选定角色必须仍是唯一的直接子控件；同名新对象、重命名、父级变化、脱离 root、时钟输入子树变化都要求停止并重新识别。列表条目或无关模板子控件正常增删不会单独使检查失败。

WindowGuard 仅接受当前进程、当前线程窗口，建立独立的原生属性标记，保存显示器句柄/设备名/区域/工作区和窗口 DPI。当窗口销毁、标记丢失或被替换时失效，避免只根据可重用的 HWND/PID 续用会话。释放时仅删除仍属于本实例的标记，保留竞争写入；标记不安装 subclass 或 hook。它核对的是运行快照，不重新解析稳定物理设备路径；生产宿主仍需在显示拓扑变化时重新解析选择，不能保证检测两个检查之间外观完全相同的拔插。

检查接入启动前后、有效更新/心跳批次前后、watchdog poll 与输入发布前。失败走同一 stop：先停用/解除输入，再恢复可见性、模型与时钟，成功后释放身份引用和窗口标记；显式 Stop 不要求旧结构仍有效。输入检查期间临时取出 Session，避免 COM 重入与可变借用冲突，验证失败不发布点击且保留默认输入。检查与批次中的同步回调不是一项原子操作，变化最迟在下一次检查时触发恢复。

新增 11 个原生隔离场景：目标重命名后停止、启动前结构变化、真实 ItemsControl 集合增删、无关模板变化、来源变化拒绝续租、活跃时出现重复角色、点击前失效、同名时钟替换后重新捕获原值、watchdog 定时器恢复脱离的根、窗口标记竞争/12 次回收，以及真实销毁本进程窗口后拒绝继续使用。当前合计 60 项单元测试和 101 项原生隔离检查。没有执行真实 Explorer 接入、显示器插拔或 DPI 设置修改；自动重新发现和 Explorer 重连仍待实现。

## 预览宿主恢复与状态界面
