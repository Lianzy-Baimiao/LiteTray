### r3 的 8037 客体故障记录

8037 最初绑定的 r3 运行编号为 `sandbox-20261109-165908-3e5f3add`。在准备启动时客体再次蓝屏；当前运行没有完整 worker/ready/grant/结果，不能使用同客体中的旧 r2 记录作本轮验收。只读事件诊断 `sandbox-20261109-170848-4be86645` 的归档 SHA-256 为 `523ec7fa760b1a73fd92e0b502f9dc11689d68e96d9dc9c231d41e480056742b`。

新转储 `110926-17484-01.dmp` 为 385,655 字节，SHA-256 为 `addeca00afe25ac356624621f708fc558a844f012f1037e4bf294b5cd6c17fbe`。匹配符号仍定位到 `svchost.exe` 的 ETW 性能计数器调用链和 `nt!HalpAllocatePmcCounterSetEx+0x1c1` 的 `rdpmc`，异常为 `0x3B / 0xC0000096`。详细分析保存在 `local/compatibility-traits/tools/kernel-debug/8037-r3-kernel-analysis.txt`。这次失败保留为模拟器客体的内核路径故障，不登记为产品检查通过。

客体正常关机后，将模拟 CPU 从 `max` 改为 `max,vendor=GenuineIntel,pmu=off`。QMP 完整模型和两颗 realized CPU 对照显示唯一改变是 vendor；PMU 原本已关闭，Windows 文件、测试包、脚本、断言与超时均未修改。该配置下首轮 `sandbox-20261109-172537-8b7d6d98` 完成四项基线检查（含 168 项 XAML）与私有 source 检查，但真实任务栏步骤返回通信超时 `1460`，实际 exit 1、并非外层超时；未得到活动时钟采样，托盘与磁盘副本检查未执行。清理收到确认且 Explorer 身份保持，仍不能把此轮登记为完整六项验收通过。归档 SHA-256 为 `a5adbe7289e00b399ac21b8c0bf82da3f0b9f13d0cb4062d5fa5caa27a8a56c6`。

源码与原始报告将这次通信失败限定在首次 `Start` 的命令发送（1500ms）或随后的 Active 状态查询（1000ms），现有错误文本不能区分两者。Prepared 已确认，不能宣称从未写入。其后的清理取得 Stop 应答与原端点的 Closed 确认；最终导出的全部 taskbar 字段与基线一致，Explorer PID 2168、线程 2612、窗口 131184 及进程启动时间保持不变。这证明失败后完成了本次可观测恢复，不能替代缺失的三帧更新、托盘准备及完整验收。`after.changes_applied=false` 仅说明探针本身只读，不是未发生接管写入的证明。

保留该失败并确认旧会话关闭后，正常关机、相同 CPU 设置重新启动，以同一 r3 包、脚本、超时和断言执行唯一一次新轮次 `sandbox-20261109-183510-a9248903`。启动器返回 `Microsoft.Management.Infrastructure.CimException`，归档没有当前轮 preflight、nonce、worker 或产品检查输出证据。归档的 365 个文件与上轮关机归档逐个文件名及 SHA-256 相同，不能用其中的旧结果代替本轮结果；该轮没有可登记的产品进程退出码。串口异常文本不能区分外层 `Win32_ComputerSystem` 与 helper 前置 `Win32_Process` 查询，也未保留可判读的中文原因，不推断具体错误码。新归档 SHA-256 为 `8276e5a888e13dfb3d4f3966eddf0e4e1c4f993342ac9fd907653309b4b5e057`。

因此，8037 保留既有参考模块与 r2 基线，**本次 r3 未完成该系统的整包验收**；首次 Start 超时的精确内部原因仍未证实。没有放宽测试断言、改写 Windows 文件或把启动器失败标成产品通过。
