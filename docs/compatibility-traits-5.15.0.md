# 5.15.0 模块特征识别验证

本次验证针对按模块独立识别、严格实现等价匹配、功能协商以及 LTSC 托盘入口修正。生产实现见提交 `3b7d883d438ea71a233dd1bbbd379d8a25dd0087`，识别规则和限制见[模块识别说明](module-recognition.md)。所有结果均限于下述程序、系统模块和场景，不是所有 Windows 11 版本或所有任务栏模板已通过的声明。

## 独立系统验证

使用已安装的独立 Windows 客体及新的 qcow2 写入层，基盘通过 QEMU 显式只读打开。本轮未下载新的系统镜像，未把宿主的 Windows Sandbox 版本标签当作另一个完整系统分支。客体不联网，测试最多两台并行；产品运行于与 Explorer 相同的普通用户会话、Medium 完整性和 `WinSta0\Default` 桌面。

每轮单独绑定 run ID、nonce、进程 PID/启动时间/参数、包清单和脚本哈希。串口传输完成只表示证据收集完成，验收还核对实际进程退出码、超时状态、原始 JSON 和 Explorer 连续性。归档中可能包含基盘遗留记录，只有与当前 run ID 匹配的目录才用于判断。

| --- | --- | --- | --- |
| Windows 11 Pro 22H2 `22621.1702` | 六项原生检查、五项磁盘样本检查通过 | 四参数借用对象，拖放命中测试 | `sandbox-20261109-142155-6c8c0b10` |

## 实现等价与拒绝边界

每个完成的客体还在 Windows 目录之外复制三份模块进行五项磁盘检查。副本从未被加载或执行，原系统文件在检查后重新核对哈希。

| 样本 | 必须得到的结果 |
| --- | --- |
| 未修改的副本 | 完整图像匹配 |
| 仅修改 COFF 时间戳和 RSDS GUID/age | 三模块均为 `execution_equivalent`，携带当前身份；历史 profile ID 为空 |
| 修改托盘可执行节的一个字节 | 托盘能力拒绝，时钟磁盘能力保留 |
| 缺少托盘模块 | 托盘能力不可用，时钟磁盘能力保留 |
| 修改宿主可执行节的一个字节 | 四项任务栏能力均拒绝 |

这些副本检查验证检测和能力分类，不能当作未知托盘环境中的真实时钟降级运行验证。运行时加载的路径、完整身份、函数前缀、控件类型和 XAML root 仍必须通过适配器的独立检查。

另以 18 份实际保留的 Microsoft PE 重放生产指纹算法：18 份原始图像完整匹配、18 份仅元数据变化的图像等价匹配、134 个节内容变异全部拒绝。七组可用模块的离线函数用途重放与 53 项 Python 测试通过；普通 24H2 BASE 仍只是静态候选，26300.9711 缺少原 PE 的条目继续仅接受完整图像匹配。

## 失败记录与清理

22H2 第一次准备启动因空 CD 设备错误指定 raw 格式而被 QEMU 拒绝，尚未启动 Windows 或产品。修正启动参数后，本轮 r2 在首次产品运行即通过，无测试时间窗口重试。客体已请求正常关机，QEMU 进程退出、QMP 不可达；基盘完整 SHA-256 仍为 `5499eb0653c8fa1f5ab37b7ff2a86042452b9366fcb85ebd98ae6e13dec382aa`。

LTSC 也已正常关机，QEMU 进程退出、QMP 不可达；基盘完整 SHA-256 仍为 `edad98f628a5af081a2d0a52b0c97f2af1ae40d2a4e87041f0b1ff136282ff1b`。

8037 首轮 r2 在客体蓝屏重启后未产生当前轮完整 runner context，独立验收为失败，不能用遗留记录替代。System 1001/41 记录 `0x3B` 和异常 `0xC0000096`；现存记录止于 worker 进程创建，缺少 ready/grant/runner 结果。掉电后缺少文件不能绝对证明某段代码未执行。原始归档 SHA-256 为 `c506993c34f223ef2a39a93104fc2e2d4f3bdc90648d0f709cffcb492b60f876`。

从客体导出的 387,073 字节小内核转储 SHA-256 为 `ae7de9eab0aa9d5bbf44ab0d00edbd3126940dd81e7ae0be790ed18b116296a2`。微软调试器与匹配的 `ntkrnlmp.pdb` 定位到 `svchost.exe` 上下文中的 `nt!HalpAllocatePmcCounterSetEx+0x1c1`，故障指令 `rdpmc`，`CS=0x10`、`ECX=1`。调用链为 `NtSetSystemInformation → EtwSetPerformanceTraceInformation → EtwpUpdatePmcCounters → HalpAllocatePmcCounterSetEx`，内核为 `10.0.26100.8036`。该证据定位于 QEMU TCG 客体的内核性能计数器路径，栈中不是 LiteTray/Explorer 的任务栏调用；没有把这次蓝屏登记为产品通过。

保留失败后，在相同 CPU 设置与相同 r2 二进制上使用新运行编号复测通过，未更改系统断言或放宽超时。新归档 SHA-256 为 `5035ea5ca64d50578cae2a1631568be66a7cc9caee6f00ba4dd8de7c1fd60c94`。分析日志位于 `local/compatibility-traits/tools/kernel-debug/8037-kernel-analysis.txt`，本轮与首轮结果分别保存。

## 验收边界

本轮未完成实际日历点击、滚轮音量、托盘复制、菜单/悬停/拖放输入、多显示器或混合 DPI 验收；属性读回也不等于逐帧屏幕绘制或连续 Shell 刷新计数。新代码、新 RVA、新 XAML 模板不能仅凭版本相近自动放行。

兼容性页的内置历史目录绑定旧包对应的模块和解析方案。本轮 LTSC 更换托盘入口后，不会继承旧入口的准备记录；新包的独立运行结果记录在本文。21H2、普通 24H2 的完整安装客体、26H1、ARM64、未收录的累计更新和未知控件结构仍待分别适配与验证。
