## 早期宿主的实际差异

早期实现使用五个已核对的宿主角色，缺少较新方案的 FrameHeight 角色和工厂虚表。通过保有引用的宿主读取 `host + 0x20 → child + 0x10 → source`，再通过真实 source 的 Content 接口取得根节点，不猜造元素偏移。

子宿主虚表位于映像的可写数据节区。专用 `xaml_explorer_host_child_xfg_v1` 方案核对完整 13 个入口、各入口字节、映像归属和内存权限，再进行首次接口查询；没有放宽其他方案的数据节区规则。离线取证同时核对 DIR64 重定位、返回值、共享引用保有/释放和 XFG 调用方式。

实验资料仅包含宿主和 shell 两个模块。托盘模块、ABI、用途和入口必须同时存在或同时缺省；不允许用占位地址凑成完整资料。磁盘报告中的时钟匹配状态仍要求后续真实结构检查，托盘明确不可用。

检查和接管现在使用相同的 source 解析路径。检查过程中保有宿主、子宿主和 source 引用，直到控件遍历结束。

## 真实客体发现的接口差异

独立安装的 `22000.318` 客体已完成五项只读命令；独立窗口内的 XAML 时钟 168 项通过，但最初的真实任务栏检查返回 `E_NOINTERFACE`，控件树为空。命令退出码为 0 仅表示报告生成成功，不能将其作为任务栏兼容通过。

增加查询阶段说明后，运行 `sandbox-20261110-140529-269bb2e1` 明确将错误定位到第一处私有子宿主接口查询；尚未执行后续 `IDesktopWindowXamlSource` 查询。检查前后为同一个 Explorer，未接管时钟。

精确映像与 PDB 表明两代 `IXamlExplorerHostChildWindow` 使用不同 IID：早期 13 槽接口是 `eef8f632-6c0d-5fcb-b6a1-354819e51f3b`，后期接口是 `ec97afd0-5c0d-581b-9508-074773c6f1e0`。早期 `find_interface` 的 GUID 比较及 `GetIids` 列表均指向前者，返回实现对象 `+0x10` 的子接口。只复用名称和字段偏移不足以证明接口兼容。

解析器改为在模块及具体虚表验证之后，按 source 实现方案查询准确 IID，并继续检查返回虚表、source 及窗口/根归属。没有按系统显示版本分支，也没有失败后试探任意接口或跳过所有权检查。原始失败及修复复测分别保存，实验资料仍须通过真实控件和接管恢复验收后才能进入默认目录。

修复包的实际只读运行 `sandbox-20261110-141737-b124c1c6` 已成功查询子接口及 `IDesktopWindowXamlSource`，并通过 source/窗口绑定检查。读取到的四个节点为 `Canvas → Taskbar.TaskbarFrame → TaskbarFrameBorder → TaskbarFrameRepeater`；没有时间/日期节点，仍不能接管时钟。该结果要求继续查明独立通知区域的宿主路径，不能把图标区域当成时钟区域。五项命令完成，独立时钟 168 项通过，同一 Explorer `4788` 保持运行，未执行时钟写入。

本轮冻结修复包 EXE SHA-256 为 `25d7f0b036d1c87d3701dd64d1536f11dbce4a90ad2702e0fb14b02d97c929e1`，适配器为 `7c0c1ee0f80860098eaa6bc4363cb3e7f37abdeec935ed04ec9cb18f197544ac`，实际检查报告为 `ca9a3069d1e112f90873def54747bcb6327a618f8c4efd7697670f70cf4aa3d7`。结果及外层身份校验保存在 `fresh21/readonly-candidate-early-qi-r5-*`，原先两轮接口失败报告保留。

这证明的是结构解析规则可复用。该组合没有已安装系统的一致性证据，不代表 `3260` 已完成运行验收。托盘矩形入口仍未通过，未生成生产资料。全程新增下载约 73.8 MiB，包含系统模块、三个 PDB 和元数据，没有下载 ISO 或 MSU。

## 独立通知区域与单文本时钟

只读枚举证明此实现的时钟位于 `Shell_TrayWnd → TrayNotifyWnd → DesktopWindowContentBridge`，与之前读取的任务栏图标 XAML 岛分离。精确 Taskbar 映像及 PDB 的构造/调用证据给出站点到组件、组件到通知宿主的字段链；解析器先验证具体组件虚表、共享引用控制块和复制/释放入口，再保有宿主，按该实现的准确 IID 查询 child/source。source 的真实父窗口必须与宿主保存的 TrayNotifyWnd 相同，三层窗口还必须属于同一 Explorer UI 线程。

`notification_area` 是可选实现资料，只允许与早期 XFG source 和不含托盘入口的组合使用；现代直接父窗口路径保持原来的检查。活动绑定仍核验显示器、工作区和 DPI。停止恢复则核验原窗口生命周期、父子关系和 source 内容，不因旧显示快照变化阻止当前对象恢复。这里修正的是绑定恢复接口的一致性；它不是已经复现的 clock-only Stop 故障，当前通知区候选也没有托盘重挂接能力。

只读运行 `sandbox-20261110-152135-3302b17c` 返回完整 108 节点树（面板内 106 个），无 source/几何错误，Explorer `4788`、UI 线程 `1700` 保持不变。实际时钟为 `SystemTray.DateTimeIconContent → ContainerGrid → DateTimeInnerTextBlock`，时间和日期同在一个 TextBlock。旧解析器要求两个文本控件，因此本次只读结果仍明确记录 `clock=null`，没有执行接管。原始检查 SHA256：`87ee8118ab8e3b490048aa5bb0552fd2ccdc1b4d1cf9d35e65f96df643bce085`。

新增适配按上述真实结构选择 `text_layout=combined`，要求文字容器独占一个 TextBlock、可见且尺寸有效，并位于能与通知铃铛分离的时钟 IconView 内；混合两种布局、重复文本、未知父类或铃铛进入文字容器均拒绝。未按 Windows 版本号放行。仅保存一份原文本、字体和宽度，注册一个原生文字刷新监听；自定义两行合并显示，停止时恢复系统最近一次原生更新。此原生控件的两行共用第一行的字体、颜色和对齐，不能分别设置两行样式。

五项独立通知绑定检查和六项单文本时钟检查已在实际发布模式 EXE 的隔离 XAML 进程通过，共 179 项；未访问 Explorer。单文本结构回归在修复前失败，修复后通过；默认与实验工作区、Clippy 和实际客体结果另行记录，不以隔离控件测试代替任务栏实测。证据位于 `local/compatibility-completion-next/combined-clock/`，独立审查在同目录 `independent-review.md`。新候选冻结于 `lab-package-r6-combined/`，EXE `8726580eb110873d76d5cb1a1839d21210aa21db965dc90627ac7955a6bdef06`，适配器 `061d36559359862adb91fef60887475e9281678a747dcac001f25c6141cf7f3a`。
